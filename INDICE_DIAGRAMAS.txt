🎯 3 FLUXOS PRINCIPAIS
────────────────────────────────────────────────────────────────────────────

FLUXO 1: Chamada de Paciente ⏱️ < 1 segundo
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Tipo:        Real-time
Atores:      Frontend, API, Backend, Database, WebSocket, TV
Crítico em:  Latência (< 1s) e sincronização em tempo real

Etapas:
  1. Médico clica "Chamar Próximo"              (< 0.1s)
  2. POST /clinic/queue/call                    (< 0.1s)
  3. Backend valida e atualiza BD               (< 0.2s)
  4. WebSocket broadcast para clientes          (< 0.3s)
  5. TV exibe nome do paciente                  (< 0.5s)
  6. Admin dashboard atualizado                 (< 0.5s)

Latências:
  ✓ Clique → API:            < 100ms
  ✓ Validação BD:            < 200ms
  ✓ WebSocket broadcast:     < 300ms
  ✓ Dashboard atualizado:    < 500ms
  ✓ TOTAL:                   < 1 segundo

Pontos Críticos:
  ⚠️ Race Condition: Usar transação com LOCK
  ⚠️ WebSocket: Fallback com polling 5s
  ⚠️ Sincronização: Backend é fonte de verdade

Dados:
  Tabela:    clinic_queue
  Índices:   (clinic_id, called_at), (status)
  Campos:    id, clinic_id, appointment_id, patient_id, room,
             called_at, called_by_user_id, status


FLUXO 2: Assinatura Digital ⏱️ 30-60 segundos
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Tipo:        Assinatura legal + Integração externa
Atores:      Frontend, API, Backend, ClickSign, WhatsApp
Crítico em:  Conformidade CFM 2.299/21 e segurança

Etapas:
  1. Médico clica "Assinar Receita"            (0s)
  2. Backend gera PDF com QR Code              (1-2s)
  3. Envia para ClickSign API                  (2-3s)
  4. Médico assina no portal ClickSign         (~30-40s)
  5. Webhook notifica backend                  (31-42s)
  6. PDF salvo e enviado via WhatsApp          (32-44s)

Latências:
  ✓ Geração PDF:      1-2s
  ✓ Upload ClickSign: < 2s
  ✓ Assinatura:       30-40s (humano)
  ✓ Webhook:          < 1s
  ✓ WhatsApp:         < 2s
  ✓ TOTAL:            30-60 segundos

Conformidade:
  ✅ Certificado ICP-Brasil
  ✅ Assinatura criptográfica (RSA-2048)
  ✅ QR Code para validação pública
  ✅ Timestamp certificado (RFC 3161)
  ✅ Hash digital SHA-256
  ✅ Proof de assinatura em BD
  ✅ Disponível para auditoria
  ✅ Lei 14.065/2020 compliant

Dados:
  Tabelas:   prescriptions, prescription_signatures
  Índices:   prescription_signatures(status)
  Campos:    prescription_id, clicksign_doc_id, signed_at,
             signature_proof (JSON), status


FLUXO 3: Anamnese (Primeira Consulta) ⏱️ 5-20 minutos
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Tipo:        Coleta de dados estruturada + Auto-save
Atores:      Frontend, Backend, Database
Crítico em:  Completude de dados e validação

As 5 Abas:
  1. 🔴 Queixa Principal
     ├─ Motivo da consulta
     ├─ Localização (8 regiões)
     ├─ Duração sintomas
     ├─ Intensidade (0-10 com cores)
     └─ O que piora/melhora

  2. 📜 Histórico
     ├─ Traumas anteriores
     ├─ Cirurgias
     ├─ Fisioterapia
     ├─ Medicações (com alertas)
     └─ Alergias

  3. ⚠️ Hábitos & Risco
     ├─ Profissão
     ├─ Atividades físicas
     ├─ Sedentarismo (slider)
     ├─ Tabagismo
     └─ Qualidade do sono

  4. 🔍 Exame Físico
     ├─ Amplitude movimento
     ├─ Testes específicos
     ├─ Inflamação
     └─ Deformidades

  5. ✅ Resumo & Assinar
     ├─ Preview colorido
     ├─ Barra de progresso
     ├─ Validação final
     └─ Assinatura digital (ClickSign)

Funcionalidades:
  💾 Auto-save: A cada campo (< 0.5s)
  ✓ Validação: Campos obrigatórios, interações
  📊 Progresso: Barra em tempo real
  🔐 Assinatura: ClickSign integrado
  📱 Follow-up: Versão simplificada para retornos

Dados:
  Tabela:    patient_anamnesis
  Índices:   (patient_id, created_at)
  Campos:    data_chief_complaint (JSON), data_history (JSON),
             data_habits (JSON), data_physical_exam (JSON),
             status, created_by_user_id, last_edited_by_user_id
