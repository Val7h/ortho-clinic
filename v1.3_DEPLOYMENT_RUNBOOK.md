## 10. ROLLBACK PROCEDURE

**Use this procedure ONLY if critical production issues cannot be resolved within 30 minutes.**

### 10.1 Decision Criteria for Rollback

**Trigger rollback if:**
- [ ] Service unavailable (> 5 minutes)
- [ ] Error rate > 5% (sustained 5+ minutes)
- [ ] Data corruption or loss detected
- [ ] Security breach confirmed
- [ ] Database connectivity lost
- [ ] Payment processing broken

**Do NOT rollback if:**
- Single API endpoint slow (scale service instead)
- Non-critical feature broken (deploy hotfix instead)
- Minor UI issues (live update instead)

### 10.2 Rollback Steps

#### Immediate Actions (Stop the Bleeding)
```bash
# 1. Declare incident
# - Notify team immediately
# - Post on status page: "Investigating deployment issue"
# - Do not panic

# 2. Assess situation (5 minutes max)
# - Check error logs
# - Identify root cause
# - Can it be hotfixed in <30 minutes?
#   - YES: Deploy hotfix (go to Section 10.4)
#   - NO: Proceed to rollback
```

```bash
# Via Render Dashboard:

#    - Click "Rollback"

```
